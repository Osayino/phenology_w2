PHENOLOGY WEEK 2 - OPENING AND RUNNING THE SUBMISSION

1. Extract the ZIP completely, keeping its folder structure. Open the extracted
   project folder in VS Code. The main notebook is casework/case_notebook.ipynb.

2. Install Python 3.11, then open a terminal in the extracted project folder and
   create a fresh environment:

   python -m venv .venv

   Install the pinned dependencies with the command for your operating system:

   Windows:
   .venv\Scripts\python.exe -m pip install -r requirements-lock.txt

   macOS / Linux:
   .venv/bin/python -m pip install -r requirements-lock.txt

   Python 3.11 and these pinned dependencies were tested on Windows. The macOS
   and Linux setup commands are provided for convenience; those systems have
   not been tested. Internet access is needed to install dependencies. The
   assignment data is included, so running the notebook needs no data download.

3. Install the Python and Jupyter extensions in VS Code. Open the notebook and
   select the newly created .venv Python environment as its kernel.

4. Use Run All to execute the notebook from top to bottom. The configuration
   cell finds the project when the kernel starts in the project root or its
   casework folder. For another launch location, set PROJECT_DIR in that cell
   to the extracted project folder. Check the printed image and mask paths.

The submission includes the two required helpers, casework/phenology_data.py and
casework/knn_utils.py, plus 37 noon JPEG images in raw/images/1 and all 22 ROI
masks in raw/masks. Keep these files alongside the notebook.

The recurrence-image cache is generated automatically and occupies about
1.53 GiB. Allow at least 4 GB of free disk space for the project, cache and
generated files. A full run may take around 20 minutes; timing depends on the
computer and whether a usable cache already exists.

The notebook opens with its saved results available for review. Running it again
recomputes results and writes files under results/; saving the notebook also
saves its new cell outputs. Read README.md for the project layout and details.

OPTIONAL: REPRODUCE THE ADDITIONAL MODEL COMPARISON

The earlier model-family section verifies and displays saved results by default. The
core environment above is enough to view it; PyTorch is not needed. The optional
comparison adds SVM, a multinomial logistic GLM, XGBoost, two Bayesian classifiers,
pretrained CNN transfer features and pretrained vision-transformer features.

To refit these models, first run the core notebook to prepare the pixel dataset
and recurrence cache. Then, from the project root, create a separate environment:

   python -m venv .venv-experiments

   Windows:
   .venv-experiments\Scripts\python.exe -m pip install -r requirements-experiments-lock.txt
   .venv-experiments\Scripts\python.exe -B experiments/run_comparison.py --fit

   macOS / Linux (not tested):
   .venv-experiments/bin/python -m pip install -r requirements-experiments-lock.txt
   .venv-experiments/bin/python -B experiments/run_comparison.py --fit

Allow roughly one additional CPU hour, depending on your computer, plus disk
space for the larger environment and feature caches. Internet access is needed
to install dependencies and download pretrained weights the first time. The
models use the original split; their settings are selected using validation.
Original baseline result files are preserved. Reopen or rerun the notebook's
model-family comparison cells to display the newly saved results.

Large fitted models and embedding caches are regenerated by --fit and are not
included in the ZIP. The saved predictions, selection record, validation scores
and plot are included so the comparison can be reviewed without this extra run.

FINAL SPATIAL AND TEMPORAL EXTENSIONS

The last notebook sections compare a matched raw-RGB GLM, a GLM with neighborhood
statistics, and a small temporal CNN trained on those statistics. Run All checks
their saved predictions using the core environment. It does not retrain them;
no GPU, PyTorch installation, or model-weight download is needed for this path.

The additional regions are used for validation, not additional training. The
experiments use 10,113 buffered fitting pixels and all 14,105 original test
pixels. The 30,114 validation pixels cover four species; the other two species
have no additional validation region. The notebook explains this limitation.

To verify the saved extension results separately from the notebook:

   python -B checks/check_spatial_results.py
   python -B checks/check_temporal_context.py

Use the core environment's Python for these commands. Optional training scripts
are experiments/spatial_context.py and experiments/temporal_context.py. Their
--fit and --evaluate stages refuse to overwrite an existing experiment record.
For a reproduction, use a separate copy of the project and move the corresponding
spatial_context_* or temporal_context_* files from results/ into a backup folder
in that copy. The temporal script requires the optional experiment environment;
the spatial script uses only the core environment. Keep the submitted records
for comparison with the reproduced results.
